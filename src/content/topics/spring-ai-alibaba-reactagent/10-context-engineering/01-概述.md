# 上下文工程 (Context Engineering)

构建 Agent 的难点不在于写出一个能跑的 Demo，而在于让它在生产环境中**稳定可靠**地运行。

当 Agent 失败时（例如胡言乱语、调用错误的工具），根本原因通常不是模型不够聪明，而是我们没有给它提供**正确**的上下文。

**上下文工程 (Context Engineering)** 就是指：以正确的格式、在正确的时间，向模型提供正确的信息和工具。

## Agent 的上下文类型

我们可以将 Agent 涉及的上下文分为三类：

| 上下文类型 | 描述 | 示例 |
| :--- | :--- | :--- |
| **模型上下文 (Model Context)** | 直接发送给模型的内容 | System Prompt, 消息历史, 可用工具列表 |
| **工具上下文 (Tool Context)** | 工具执行时依赖的环境信息 | 用户 ID, 数据库连接, API Key |
| **生命周期上下文 (Lifecycle Context)** | 在 Agent 运行过程中产生和维护的状态 | 中间推理结果, 错误重试计数, 审计日志 |

## 1. 模型上下文 (Model Context)

这是最直接影响模型表现的部分。

### 动态 System Prompt

不要写死 System Prompt。根据用户的身份、当前的时间、之前的交互历史，动态生成 System Prompt。

```java
// 伪代码示例
String systemPrompt = """
    你是一个智能助手。
    当前用户: %s
    当前时间: %s
    用户偏好: %s
    """.formatted(userName, LocalDateTime.now(), userPreferences);
```

### 消息历史管理

不要无脑地将所有历史消息都塞给模型。
- **修剪 (Trimming)**: 只保留最近 N 轮。
- **摘要 (Summarization)**: 将旧消息压缩成摘要。
- **过滤 (Filtering)**: 去除无关的寒暄，只保留关键信息。

## 2. 工具上下文 (Tool Context)

工具通常是无状态的函数，但它们往往需要访问当前的运行时环境。

在 Spring AI Alibaba 中，可以通过 `ToolContext` 或 `ThreadLocal` 将上下文传递给工具。

```java
public class OrderTools {

    @Tool(description = "查询我的订单")
    public String getMyOrders() {
        // 从上下文中获取当前用户 ID
        String userId = UserContextHolder.getUserId();
        return orderService.findOrdersByUserId(userId).toString();
    }
}
```

## 3. 生命周期上下文 (Lifecycle Context)

利用 **Hooks** 和 **Interceptors** 来管理这部分上下文。

- **错误处理**: 当工具执行失败时，将错误信息作为上下文反馈给模型，让模型尝试自我修正。
- **状态监控**: 记录每一步的 Token 消耗，防止成本失控。

## 数据源

在进行上下文工程时，我们需要从不同的数据源获取信息：

1. **Runtime Context (运行时上下文)**: 会话级别的静态配置（如 User ID）。
2. **State (状态)**: 短期记忆，随会话变化（如当前对话历史）。
3. **Store (存储)**: 长期记忆，跨会话持久化（如用户画像、知识库）。

## 总结

上下文工程是 AI 工程师的核心竞争力。通过精细化地管理上下文，我们可以显著提升 Agent 的智商和稳定性，使其从"玩具"进化为"工具"。
