# Agent 作为工具 (Agent as Tools)

在处理复杂任务时，单个 Agent 往往力不从心。它可能需要掌握太多的工具，导致 Prompt 过长，或者在不同领域的知识之间产生混淆。

**Multi-Agent（多智能体）** 架构通过将任务分解给多个专业的 Agent 来解决这个问题。其中一种最常见的模式是：**将一个 Agent 封装为工具，供另一个 Agent 调用**。

## 为什么需要 Multi-Agent？

1. **专业化**：每个 Agent 专注于一个领域（如一个负责写代码，一个负责写文档）。
2. **模块化**：可以将复杂的系统拆分为独立的、可测试的模块。
3. **上下文隔离**：每个 Agent 维护自己的上下文，避免无关信息干扰。

## 核心模式：Supervisor (监督者) 模式

在这种模式中，有一个主 Agent（Supervisor 或 Controller），它不直接执行具体任务，而是负责：
1. 理解用户意图。
2. 决定调用哪个子 Agent（Sub-Agent）。
3. 接收子 Agent 的结果。
4. 整合结果并回复用户。

子 Agent 对主 Agent 来说，就是一个**工具**。

## 实现步骤

在 Spring AI Alibaba 中，我们可以使用 `AgentTool` 将一个 `ReactAgent` 包装成一个 `FunctionCallback`（即工具）。

### 1. 创建子 Agent

首先，我们创建一个专注于特定任务的 Agent，例如一个"作家 Agent"。

```java
import com.alibaba.cloud.ai.graph.agent.ReactAgent;

ReactAgent writerAgent = ReactAgent.builder()
    .name("writer-agent")
    .model(chatModel)
    .description("一个专业的作家，擅长撰写各种风格的文章。") // 这个描述很重要，主 Agent 会根据它来决定是否调用
    .instruction("你是一个作家。请根据用户的要求撰写文章。")
    .build();
```

### 2. 将子 Agent 封装为工具

使用 `AgentTool.getFunctionToolCallback()` 方法。

```java
import com.alibaba.cloud.ai.graph.agent.AgentTool;

FunctionCallback writerTool = AgentTool.getFunctionToolCallback(writerAgent);
```

### 3. 创建主 Agent

将封装好的工具注册给主 Agent。

```java
ReactAgent mainAgent = ReactAgent.builder()
    .name("main-agent")
    .model(chatModel)
    .instruction("你是一个智能助手。如果用户需要写文章，请调用 writer-agent。")
    .tools(writerTool) // 注册子 Agent 工具
    .build();
```

### 4. 运行

```java
// 用户请求写文章
mainAgent.call("帮我写一篇关于 Spring AI 的 100 字简介。");

// 流程：
// 1. mainAgent 分析意图，决定调用 writer-agent 工具。
// 2. writerAgent 启动，接收任务，生成文章。
// 3. writerAgent 返回文章内容给 mainAgent。
// 4. mainAgent 将文章返回给用户。
```

## 进阶：多层级协作

你可以构建更复杂的层级结构。例如：
* CEO Agent
  * CTO Agent
    * 后端开发 Agent
    * 前端开发 Agent
  * CPO Agent
    * 产品设计 Agent

每个上级 Agent 都将下级 Agent 视为工具。

## 总结

将 Agent 作为工具使用，是构建强大 Multi-Agent 系统的基石。它允许我们以搭积木的方式，组合出能够处理极高复杂度的智能应用。
